# A team chat that has run for three weeks: the owner talks to PM in short
# sessions in #general (4–5 rounds each), and PM's task threads in #app stay
# under 6 rounds. Decisions are planted at different distances from the end;
# the probes at the bottom ask about them.
#
# Format:
#   == channel NAME                       following messages go to #NAME
#   == thread CHANNEL "NAME" by AUTHOR    AUTHOR opens a new thread in #CHANNEL;
#                                         following messages go into it
#   -- day -N HH:MM                       clock for the next messages (days
#                                         before today; +2 min per message)
#   Author: text                          a message; "Owner" is you
#     continuation                        (indented) another line of it
#   {date:+N}                             today + N days, as M/D
#   !! decision ID key=W[|W] [replaces ID]: text   (~ is a space in W)
#                                         the message above settles something:
#                                         it should end up in the log, in an
#                                         entry with one of the words W; `text`
#                                         is the oracle log's wording
#   !! status ID                          the message above settles nothing:
#                                         capture expects no record
#
#   ?? ID @CHANNEL TAG                    a probe asked at the end of #CHANNEL,
#   ?? ID @thread:CHANNEL TAG             or in a new thread there
#   F: text                               the message that holds the answer
#   Q: question
#   A: alt|alt                            all A lines must match (any alt each)
#
# TAG is how far back the fact is when the probe is asked in #CHANNEL: near
# (< 40 messages, inside the default window), mid (40–99: read_channel can
# still reach it), far (100+: nothing reaches it). Probes in a new thread
# are "cross". The example's tests check the tags against the real distances.
